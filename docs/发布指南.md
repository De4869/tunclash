# 发布到 GitHub / 模块仓库

## 0. 会提交什么（以及不会提交什么）

`.gitignore` 已经排除：

| 排除项 | 原因 |
|---|---|
| `_tools/` | 本地调试产物：订阅地址、抓包、测试配置、日志 |
| `dist/` | 构建产物（APK / 模块 zip / 配置备份） |
| `Android/local.properties` | 本机 SDK 路径 |
| `Android/**/build/`、`.gradle/`、`.kotlin/` | 构建缓存 |
| `module/bin/`、`module/geo/`、`Android/app/src/main/assets/*` | 大二进制（用脚本拉取） |
| `*.apk`、`*.zip`、`*.jks` | 产物与签名 |

> 提交前可自查：`git grep -nE "subscribe\?token=|/api/v1/client/subscribe"`，应当没有任何命中。

## 1. 初始化并推送到 GitHub

```bash
cd 透明代理
git init
git add .
git commit -m "feat: mihomo root tproxy app + KSU module with WebUI"

# 先在 GitHub 网页上新建空仓库（不要勾选 README）
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

用 Token 推送时地址写成 `https://<用户名>:<PAT>@github.com/<用户名>/<仓库名>.git`（PAT 勾选 `repo` 权限）。

## 2. 本地构建

```bash
bash scripts/fetch-deps.sh            # 下载 mihomo 内核 + geo 数据库
cd Android && ./gradlew assembleDebug # 产物：app/build/outputs/apk/debug/app-debug.apk
```

## 3. 发布 Release（自动）

打 tag 即可触发 `.github/workflows/release.yml`：

```bash
git tag v1.0.0
git push origin v1.0.0
```

工作流会：拉依赖 → 编译 APK → 打包模块 → 生成 `update.json` → 创建 Release 并挂上
`MihomoTProxy-v1.0.0.apk`、`MihomoTProxy-Module-v1.0.0.zip`、`update.json`。

## 4. 让管理器能「检查更新」

模块的 `module.prop` 里有：

```
updateJson=https://github.com/USER/REPO/releases/latest/download/update.json
```

把 `USER/REPO` 换成你的仓库即可（根目录的 `update.json` 也同步改一下，仅用于本地测试）。
之后 KernelSU / SukiSU / Magisk 管理器里对该模块就会出现「更新」入口，读取的就是 Release 里的
`update.json`：

```json
{
  "version": "v1.0.0",
  "versionCode": 1,
  "zipUrl": "https://github.com/USER/REPO/releases/download/v1.0.0/MihomoTProxy-Module-v1.0.0.zip",
  "changelog": "https://raw.githubusercontent.com/USER/REPO/main/CHANGELOG.md"
}
```

## 5. 关于「上传到 SukiSU 的仓库」

SukiSU Ultra / KernelSU 本身没有官方的「模块商店」，常见的分发方式是：

1. **GitHub Release + update.json**（推荐，上面已经做好）——管理器直接检查更新；
2. 社区维护的模块列表仓库（Magisk/KSU 模块索引类项目）通常接受 PR，提交时给：
   - `module.prop`（含 id / version / versionCode / updateJson）
   - 一个可访问的 Release 直链（zipUrl）
   - 简短说明与截图；
3. 论坛/频道（如酷安、Telegram 群）发帖时同样贴 Release 链接。

> 注意：模块 id 一旦发布就不要改（`mihomo_tproxy`），否则会被识别成新模块。

## 6. 仓库结构

```
Android/                 App 源码（Kotlin + Compose）
module/                  模块脚本 + WebUI（大文件由脚本拉取）
scripts/fetch-deps.sh    拉取 mihomo / geo
docs/                    测试记录、发布指南、截图
update.json              模块更新元数据（Release 时用工作流生成的版本覆盖）
.github/workflows/       tag 触发构建与发布
```
