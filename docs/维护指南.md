# 维护与自动化（GitHub）

## 1. 上传（你这边三条命令）

```bash
cd 透明代理
bash scripts/set-repo.sh <用户名>/<仓库名>
git add -A && git commit -m "chore: set update channel"
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

之后每次发版：

```bash
git tag v1.1.0 && git push origin v1.1.0
```

CI 会自动：拉 mihomo/geo → 跑单测 → 编译 APK → 打包模块 → 生成 `update.json` → 建 Release。
管理器的「检查更新」读的就是 Release 里的 `update.json`。

## 2. 让我（AI）直接操作仓库

两条路，任选：

**A. 本机装 GitHub CLI（推荐，长期）**

```bash
winget install --id GitHub.cli -e
gh auth login          # 选择 HTTPS + 浏览器登录
gh auth status
```

登录后我就能直接：`gh repo create`、`git push`、`gh issue list/comment/close`、
`gh pr create/merge`、`gh release create`，不需要你把 token 贴在对话里。

**B. 临时给一个 fine-grained token（用完可撤销）**

- 权限：Contents: RW、Issues: RW、Pull requests: RW、Actions: R（可选）
- 只授权到这一个仓库，有效期建议 7–30 天
- 我只在单次命令里使用，不写入 `.git/config`

## 3. 反馈闭环（装上 Issue 表单之后）

```
用户提交 issue（模板会强制填版本/设备/日志）
      ↓  我：gh issue list --label bug
复现 & 定位（本地起内核 / 看用户日志）
      ↓
改代码 + 补单测 → PR → CI 绿
      ↓
打 tag → Release（APK + 模块 + update.json）
      ↓
用户管理器「检查更新」→ 一键升级
      ↓
我在 issue 里回复修复版本并 close
```

常用命令（我以后会这样干活）：

```bash
gh issue list --state open --label bug
gh issue view 12 --comments
gh issue comment 12 --body "已在 v1.1.1 修复，请更新后重试"
gh issue close 12
gh release create v1.1.1 --generate-notes
```

## 4. 建议长期开着的东西

| 项目 | 作用 |
|---|---|
| `.github/workflows/ci.yml` | 每次 push/PR 编译 + 跑单测，防止合并坏代码 |
| `.github/workflows/release.yml` | 打 tag 自动发 Release 和 update.json |
| `.github/dependabot.yml` | 依赖每周自动提 PR（Compose / AGP / Actions） |
| Issue 表单 | 强制用户给版本、设备、日志，省一轮来回 |
| Release notes | `gh release create --generate-notes` 自动汇总 PR |

## 5. 注意

- **不要**把 `dist/config-app-backup.yaml`、`appdata-backup.tgz`、`_tools/` 推上去（已 gitignore）；
- token 别 commit、别贴进 issue；泄露就在 GitHub 设置里 Revoke；
- 模块 `id`（`mihomo_tproxy`）发布后不要改，否则管理器会当成新模块。
